# Vercel 배포 안내

ShopMate를 인터넷에 올리는 방법. **비개발자 기준**으로 적었다.
낯선 단어는 [`GLOSSARY.md`](GLOSSARY.md)를 본다.

---

## 사전 점검 결과 — 코드는 고칠 것이 없다

| 항목 | 상태 |
|---|---|
| 빌드가 열쇠(환경변수) 없이도 되는가 | ✅ 됨 |
| 열쇠를 언제 읽는가 | ✅ 필요한 순간에만. 빌드를 막지 않는다 |
| 열쇠 없을 때 사이트가 죽는가 | ✅ 안 죽는다. 미들웨어가 그냥 통과시킨다 |
| 상품 사진 외부 주소 | ✅ 별도 설정 불필요 (`<img>` 사용) |
| Node 버전 | ✅ `.nvmrc` 에 22 |
| `vercel.json` 같은 설정 파일 | 불필요. Vercel이 Next.js로 자동 인식한다 |

---

## 시작 전에 알아둘 것

배포하면 **인터넷의 누구나 들어온다.** 그리고 Supabase 프로젝트는 실습용 하나뿐이다.

- 누구나 회원가입할 수 있다
- 누구나 **판매자로** 가입해 상품을 올릴 수 있다 (판매자 심사는 MVP에서 뺐다 — ADR-016)
- 그 데이터가 실습 데이터와 같은 곳에 쌓인다

실습 목적이면 그대로 진행해도 된다. **다만 주소를 아무 데나 공유하지 않는다.**
운영용을 분리하고 싶으면 Supabase에서 프로젝트를 하나 더 만들어 열쇠만 바꿔 넣으면 된다.

---

# 1단계 · Vercel 가입 + GitHub 연결 (3분)

1. https://vercel.com → **Sign Up**
2. **Continue with GitHub** 선택
   > 이메일로 가입하지 않는다. GitHub으로 가입해야 리포를 바로 가져올 수 있다.
3. GitHub이 권한을 물으면 승인한다
   - **All repositories** 또는 **Only select repositories → shopmate**
   - 하나만 고르는 쪽이 더 안전하다
4. 요금제는 **Hobby**(무료). 카드 등록 필요 없다.

**확인**: 주소가 `https://vercel.com/<계정이름>` 형태의 빈 대시보드가 뜬다.

---

# 2단계 · 프로젝트 가져오기 (2분)

1. 대시보드에서 **Add New...** → **Project**
2. 목록에서 `shopmate` 를 찾아 **Import**
3. 설정 화면이 뜬다. **아무것도 바꾸지 않는다.**

| 항목 | 값 | 손대는가 |
|---|---|---|
| Framework Preset | Next.js | ❌ 자동으로 잡힌다 |
| Root Directory | `./` | ❌ |
| Build Command | 기본값 | ❌ |
| Output Directory | 기본값 | ❌ |

**아직 Deploy 버튼을 누르지 않는다.** 3단계를 먼저 한다.

---

# 3단계 · 열쇠 3개 넣기 (5분) ★ 가장 실수가 잦은 곳

같은 화면에서 **Environment Variables** 항목을 편다.

## 넣을 값 3개

Supabase 대시보드 → **Project Settings → API** 에서 복사한다.

| 이름 (그대로 입력) | 값 | 어디서 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 긴 문자열 | anon / public 키 |
| `SUPABASE_SERVICE_ROLE_KEY` | 긴 문자열 | service_role 키 |

## ★ 주의할 점

- **이름을 정확히 그대로** 입력한다. 오타 하나면 사이트가 데이터베이스를 못 찾는다.
- 세 번째는 **`NEXT_PUBLIC_` 을 붙이지 않는다.** 붙이면 브라우저로 내려가 DB 전체가 열린다.
- 값 앞뒤에 **공백이나 따옴표가 섞이지 않게** 한다. 복사할 때 잘 붙는다.
- 적용 범위(Environment)는 **Production / Preview / Development 전부** 체크한다.

## 확인

세 줄이 목록에 보이면 된다. 값은 가려져서 안 보이는 게 정상이다.

---

# 4단계 · 배포 (2분)

**Deploy** 버튼을 누른다. 로그가 흐르고 2분쯤 걸린다.

## 성공하면

축하 화면과 함께 주소가 나온다.
```
https://shopmate-xxxx.vercel.app
```

## 실패하면

로그에서 빨간 글씨를 찾는다.

| 로그에 보이는 말 | 원인 | 해결 |
|---|---|---|
| `Module not found` | 빠진 파일 | 로그를 그대로 가져와 물어본다 |
| `Type error` | 코드 오류 | 로컬에서 `npm run build` 로 재현해본다 |
| 환경 변수 관련 | 3단계 오타 | Settings → Environment Variables 에서 이름 확인 |

빌드는 로컬에서 이미 통과했으므로, 실패한다면 대개 3단계 문제다.

---

# 5단계 · Supabase에 배포 주소 알려주기 (2분)

Supabase 대시보드 → **Authentication → URL Configuration**

| 항목 | 넣을 값 |
|---|---|
| Site URL | `https://shopmate-xxxx.vercel.app` |
| Redirect URLs | 같은 주소 추가 |

> **이메일 확인(Confirm email)을 꺼 두었다면** 이 단계 없이도 로그인은 된다.
> 나중에 이메일 확인을 켤 계획이면 지금 넣어두는 게 낫다.

---

# 6단계 · 실제로 눌러보기 (10분)

배포 주소를 열고 **처음부터 끝까지** 해본다. 로컬에서 됐다고 배포판도 되는 건 아니다.

## 손님으로

| | 확인할 것 |
|---|---|
| 1 | 상품 목록이 뜬다 (안 뜨면 → 3단계 열쇠 문제) |
| 2 | 상품 상세가 열린다 |
| 3 | 로그인 없이 장바구니에 담긴다 |
| 4 | 회원가입 → 로그인된다 |
| 5 | 로컬 장바구니가 서버로 합쳐진다 (수량이 두 배가 되지 않는다) |
| 6 | 판매자가 2명 이상이면 배송비가 각각 붙는다 |
| 7 | 주문이 된다 |
| 8 | 주문 내역에 나온다 |
| 9 | **결제 화면 금액 = 주문 내역 금액** |

## 판매자로

| | 확인할 것 |
|---|---|
| 10 | 판매자 계정으로 로그인 → 판매자 콘솔이 보인다 |
| 11 | 상품 등록 → 목록에 뜬다 |
| 12 | 발송 처리 → 구매자 화면에 반영된다 |
| 13 | **★ 판매자 A로 B의 상품 수정 주소에 직접 접근 → 저장 안 됨** |
| 14 | **★ 판매자 A의 주문 목록에 B의 주문이 없다** |

**13·14번이 가장 중요하다.** 이게 뚫리면 배포하면 안 된다.

## 휴대폰으로

| | 확인할 것 |
|---|---|
| 15 | 폭 375px에서 레이아웃이 안 깨지고 가로 스크롤이 없다 |

# 배포 후 알아둘 것

## 자동 재배포

`main` 브랜치에 push하면 **Vercel이 알아서 다시 배포한다.** 따로 할 일이 없다.

## 되돌리기

Vercel 대시보드 → **Deployments** → 이전 배포 → **Promote to Production**
망가진 배포를 몇 초 만에 되돌릴 수 있다.

## 열쇠를 바꿨을 때

환경 변수만 고치면 반영되지 않는다. **Deployments → 최신 → Redeploy** 를 눌러야 한다.

## 무료 한도

- Hobby 요금제는 개인 프로젝트에 충분하다
- **상업적 사용은 안 된다.** 실제로 물건을 팔면 유료 요금제가 필요하다
- Supabase 무료 티어는 오래 안 쓰면 프로젝트가 일시정지된다. 그러면 사이트에서 상품이 안 보인다 — 대시보드에서 다시 켜면 된다
