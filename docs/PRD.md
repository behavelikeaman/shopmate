# PRD: ShopMate

## 목표
여러 판매자가 각자 상품을 올리고, 구매자가 한 번에 담아 결제(모의)까지 끝낼 수 있는 최소 마켓플레이스를 만든다.

## 사용자
- **구매자** — 로그인 없이 상품을 둘러보고 장바구니에 담는다. 주문할 때만 로그인한다.
- **판매자** — 자기 상품을 등록·수정·삭제하고, 자기 상품이 팔린 건을 확인해 발송 처리한다. **남의 상품과 남의 주문은 보이지 않는다.**
- **운영자(admin)** — 판매자 콘솔에서 전체를 본다. 전용 화면은 만들지 않는다 (아래 MVP 제외 참고).

역할은 `customer` | `seller` | `admin` 셋이다. 가입 시 "판매자로 가입"을 선택하면 `seller`가 된다. **`admin`은 SQL로만 승격한다** — 스스로 운영자가 되는 경로는 UI에 존재하지 않는다.

## 핵심 기능
1. **상품 카탈로그** — 목록(카테고리 필터·이름 검색), 상세. 상세에는 판매자명을 표시한다.
2. **장바구니** — 담기/수량 변경/삭제. 비로그인은 localStorage, 로그인하면 서버 장바구니로 병합. **판매자별로 묶어서 보여주고 배송비도 판매자별로 계산한다.**
3. **인증** — Supabase Auth 이메일+비밀번호 회원가입(구매자/판매자 선택)·로그인·로그아웃.
4. **주문** — 배송지 입력 → 주문 생성(모의 결제 승인) → 재고 차감 → 주문 내역 조회. 한 번의 결제가 판매자 수만큼의 **이행 그룹**으로 쪼개진다.
5. **취소** — 아직 발송되지 않은(`paid`) 이행 그룹을 구매자가 취소할 수 있다. **취소 시 해당 그룹 품목의 재고를 되돌린다.**
6. **판매자 콘솔** — 내 상품 CRUD, 내 이행 그룹 목록 조회 및 발송/취소 처리.

## 주문 구조
한 번의 결제에 여러 판매자의 상품이 섞인다. A 판매자는 오늘 보내고 B 판매자는 모레 보내므로, **주문 상태는 주문 전체가 아니라 판매자별로 존재한다.**

```
orders          결제 단위 — 총액, 배송지, 주문 시각
  order_groups    판매자별 이행 단위 — status(paid|shipped|cancelled), 그룹 소계, 그룹 배송비
    order_items     품목 — 상품명·단가 스냅샷, 수량
```

- 발송·취소·상태 조회의 단위는 전부 `order_groups`다. `orders`에는 상태가 없다.
- 구매자의 주문 상세 화면은 그룹 단위로 나눠 보여준다 ("A스토어 · 발송완료", "B스토어 · 결제완료 [취소]").

## 배송비
**판매자별로 계산한다.** 같은 판매자 상품의 소계가 50,000원 이상이면 그 그룹은 무료, 미만이면 3,000원.

> 주문 전체 소계 기준으로 하면 A에서 3만원·B에서 3만원 산 사람이 무료배송을 받는다. 실제로는 두 판매자가 각각 따로 부치므로 성립하지 않는다.

주문 총액 = Σ(그룹 소계) + Σ(그룹 배송비).

## MVP 제외 사항
- 실제 결제 PG 연동 (토스페이먼츠·아임포트 등). 결제는 항상 성공하는 모의 처리.
- **운영자 전용 화면.** `admin`은 RLS에서 전체 접근 권한만 갖고, 화면은 판매자 콘솔을 그대로 쓴다(admin이면 전체가 보인다). 판매자 승격·강등은 SQL로 한다.
- 정산 (판매자에게 대금을 지급하는 흐름). 취소는 재고만 되돌리고 돈은 계산하지 않는다.
- 배송 추적, 반품/환불 플로우. 발송 처리는 상태 전이일 뿐 송장번호를 다루지 않는다.
- 리뷰·평점, 위시리스트, 쿠폰·프로모션.
- 이미지 직접 업로드 (Supabase Storage). 상품 이미지는 외부 URL 문자열로만 받는다.
- 소셜 로그인, 이메일 인증 메일, 비밀번호 재설정.
- 다국어, 다크모드.

## 화면
| 경로 | 접근 | 설명 |
|------|------|------|
| `/` | 누구나 | 상품 목록 + 카테고리 필터 + 검색 |
| `/products/[id]` | 누구나 | 상품 상세 + 판매자명 + 장바구니 담기 |
| `/cart` | 누구나 | 장바구니 (판매자별 그룹 + 그룹별 배송비) |
| `/checkout` | 로그인 | 배송지 입력 + 그룹별 주문 요약 + 주문 확정 |
| `/orders` | 로그인 | 내 주문 목록 |
| `/orders/[id]` | 본인만 | 주문 상세 — 그룹별 상태, 취소 버튼 |
| `/login`, `/signup` | 누구나 | 인증 (가입 시 판매자 선택) |
| `/seller/products` | seller·admin | 내 상품 목록 + 생성/수정/삭제 |
| `/seller/orders` | seller·admin | 내 이행 그룹 목록 + 발송/취소 처리 |

## 규칙 (제품 레벨)
- 재고가 0인 상품도 목록에 **등록순 그대로 노출**하고 "품절" 뱃지를 붙인다. 순서를 조작하거나 숨기지 않는다. 상세는 볼 수 있고, 담기만 막는다.
- 주문 확정 시점에 재고가 부족하면 **주문 전체를 실패**시키고 어떤 상품이 몇 개 부족한지 보여준다. 가능한 만큼만 부분 주문하지 않는다.
- 주문에는 **주문 당시의 상품명과 가격을 스냅샷으로 저장**한다. 이후 상품이 바뀌거나 삭제돼도 과거 주문 내역은 변하지 않는다.
- 취소는 `paid` 상태의 그룹에만 가능하다. `shipped`된 그룹은 구매자도 판매자도 취소할 수 없다 (반품은 MVP 제외).
- 취소 시 그 그룹 품목의 수량만큼 `products.stock`을 되돌린다. 이미 삭제된 상품이면 복구를 건너뛴다.
- 판매자는 자기 상품과 자기 이행 그룹만 볼 수 있다. 이 격리는 화면이 아니라 **RLS로 보장한다.**

## 디자인
- 라이트 모드 고정. 상품 사진이 주인공이므로 UI는 물러선다.
- 무채색(흰 배경 + 회색 계열) + 포인트 색 1가지.
- 커머스지만 "세일 배너로 도배된 쇼핑몰"이 아니라 정돈된 카탈로그처럼 보여야 한다.
- 판매자 콘솔은 밀도 우선. 카드 그리드가 아니라 테이블을 쓴다.
